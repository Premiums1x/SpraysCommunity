# 校园流浪动物图鉴与动态打卡系统 - 完整实施方案

## Context

本项目是一个课程设计项目，目标是构建一个"基于 Spring Boot 3 的校园流浪动物图鉴与动态打卡系统"。系统核心围绕"动物档案"与"日常打卡"两大业务展开，重点考核一对多（One-to-Many）关系型业务构建。当前项目处于初始状态，仅有 Spring Boot 骨架代码。

## 二、数据库设计

### 2.1 ER 关系图

```
User (1) ──── (N) CheckIn (N) ──── (1) Animal
                                      │
                                      │ 封面照片路径存储在 Animal 表
```

### 2.2 数据表结构

#### 表1: `user`（用户表）
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 用户ID |
| username | VARCHAR(50) | UNIQUE, NOT NULL | 用户名 |
| password | VARCHAR(255) | NOT NULL | 密码（BCrypt加密） |
| nickname | VARCHAR(50) | | 昵称 |
| role | TINYINT | NOT NULL, DEFAULT 0 | 角色：0=普通用户, 1=管理员 |
| avatar | VARCHAR(255) | | 头像路径 |
| create_time | DATETIME | NOT NULL | 注册时间 |
| update_time | DATETIME | NOT NULL | 更新时间 |

#### 表2: `animal`（动物档案表）
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 动物ID |
| name | VARCHAR(50) | NOT NULL | 暂定名字 |
| type | TINYINT | NOT NULL | 类型：1=猫, 2=狗 |
| area | VARCHAR(100) | NOT NULL | 常驻区域 |
| cover_image | VARCHAR(255) | | 封面照片路径 |
| description | TEXT | | 简介描述 |
| create_time | DATETIME | NOT NULL | 录入时间 |
| update_time | DATETIME | NOT NULL | 更新时间 |
| is_deleted | TINYINT | DEFAULT 0 | 逻辑删除标记 |

#### 表3: `check_in`（打卡动态表）
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 打卡ID |
| user_id | BIGINT | FK, NOT NULL | 打卡用户ID |
| animal_id | BIGINT | FK, NOT NULL | 关联动物ID |
| content | TEXT | NOT NULL | 打卡文字描述 |
| create_time | DATETIME | NOT NULL | 打卡时间 |

### 2.3 索引设计
- `check_in` 表: `idx_animal_id_create_time (animal_id, create_time DESC)` —— 支持按动物ID查询并按时间倒序
- `animal` 表: `idx_name (name)` —— 支持名字模糊查询
- `animal` 表: `idx_type (type)` —— 支持类型筛选

## 四、核心功能模块实现方案

### 4.1 用户认证模块
- **注册**：BCrypt 加密存储密码，默认角色为普通用户
- **登录**：验证用户名密码，生成 JWT Token 返回前端
- **鉴权**：JWT 拦截器校验 Token 有效性，从 Token 中解析用户信息注入上下文
- **角色控制**：自定义注解 `@RequireAdmin` 标注管理员接口，拦截器中校验角色

### 4.2 动物图鉴管理模块（管理员）
- **档案录入**：MultipartFile 接收图片 + JSON 接收动物信息，图片存储至本地 `/uploads/` 目录
- **档案检索**：MyBatis-Plus 条件构造器实现模糊查询 + 类型筛选 + 分页
- **档案删除**：逻辑删除（MyBatis-Plus `@TableLogic`）

### 4.3 打卡动态模块（用户）
- **即时打卡**：用户选择动物ID + 输入文字描述，创建打卡记录
- **时间轴查询**：根据 animal_id 关联查询 check_in 表，JOIN user 表获取打卡者昵称/头像，按 create_time DESC 分页返回

## 五、RESTful API 接口设计

### 5.1 认证模块
| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | `/api/auth/register` | 用户注册 | 公开 |
| POST | `/api/auth/login` | 用户登录 | 公开 |
| GET | `/api/auth/info` | 获取当前用户信息 | 登录用户 |

### 5.2 动物图鉴模块
| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| POST | `/api/animals` | 新增动物档案（含图片上传） | 管理员 |
| GET | `/api/animals` | 分页查询动物列表（支持模糊搜索+类型筛选） | 所有用户 |
| GET | `/api/animals/{id}` | 获取动物详情 | 所有用户 |
| PUT | `/api/animals/{id}` | 更新动物信息 | 管理员 |
| DELETE | `/api/animals/{id}` | 删除动物档案 | 管理员 |

### 5.3 打卡动态模块
| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|

| GET | `/api/animals/{id}/checkins` | 查询某动物的打卡时间轴（分页） | 所有用户 |
| GET | `/api/checkins/my` | 查询我的打卡记录 | 登录用户 |

## 六、安全性与性能优化

### 6.1 安全策略
- **密码加密**：BCrypt 哈希存储
- **JWT 认证**：无状态令牌 + 过期时间设置（如24小时）
- **参数校验**：`@Valid` + `@NotBlank` / `@Size` 等注解
- **SQL 注入防护**：MyBatis-Plus 参数化查询
- **文件上传安全**：限制文件类型（jpg/png/gif）、限制文件大小（如5MB）、重命名文件（UUID）
- **CORS 配置**：仅允许前端域名访问

### 6.2 性能优化
- **分页查询**：MyBatis-Plus 分页插件，避免全表扫描
- **索引优化**：针对高频查询字段建立复合索引
- **逻辑删除**：避免物理删除导致的数据不一致
- **文件存储**：静态资源路径映射，由 Nginx/Spring 直接返回

## 七、任务分解与实施顺序

### Task 1: 后端基础架构搭建
- 添加 Maven 依赖（MyBatis-Plus、Spring Web、Validation、JWT、Knife4j）

- 编写 SQL 建表脚本（user、animal、check_in）

- 创建 Mapper 接口

- JWT 工具类（生成/解析 Token）
- 登录注册 Service + Controller
- JWT 拦截器 + 角色校验注解

- Animal Service（CRUD + 分页 + 模糊查询）

- Axios 封装（请求/响应拦截器、Token 管理）

### Task 7: 前端页面开发
- 登录/注册页面

### Task 8: 联调与测试

## 九、验证方案

1. **后端验证**：使用 Knife4j Swagger UI 测试所有接口（注册→登录→获取Token→带Token访问受保护接口）
2. **前端验证**：在浏览器中完成完整用户流程：注册→登录→浏览动物→发布打卡→查看时间轴→管理员添加动物

4. **安全验证**：未登录用户无法访问受保护接口、普通用户无法调用管理员接口
